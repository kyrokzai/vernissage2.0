## 1. Как устроен studiochenille.com

Изучено в Playwright на компьютере (Chromium 1440) и iPhone (WebKit), по исходному коду `hero-journey.js` (35 КБ) и манифесту кадров. Кейс разработчика: kaev.ai/work/studio-chenille.

**Что видит посетитель.** Один непрерывный кадр около 7,4 с, без склеек: вечерний фасад особняка → ступени → открытая дверь → холл → кухня. Это ИИ-съёмка, в коде так и сказано. В конце она растворяется в **настоящей фотографии их работы**: «путь всегда приземляется на реальную работу студии». Текст минимальный: название, затем «Step inside a home designed around you» и две кнопки.

**Технология — своя, на чистом JavaScript.** GSAP, Lenis и Three.js не используются.

| Что | Как у них |
|---|---|
| Закрепление | CSS `position: sticky`, на `<body>` `overflow-x: clip`. Прокрутка родная |
| Телефон | Отдельная вертикальная съёмка: **108 кадров WebP 900×1600** (≈ 4 МБ) на `<canvas>`, плотность ≤ 2. Кадры не растягиваются, а уменьшаются |
| Компьютер | **155 кадров WebP 1280×720.** Для экранов от 1441 физ. px — MP4-ярусы **1440p и 2160p** с ключевым кадром через каждые 6 кадров. Файл скачивается целиком в память, перемотка идёт по локальным байтам |
| Страховка | Устройство само замеряет время перемотки. Если медиана > 40 мс, движение переходит на кадры WebP, а MP4 только дорисовывает резкий кадр в паузе |
| «Тяжёлая камера» | Сглаживание `k = 1 − e^(−7·dt)`: камера догоняет прокрутку за ~0,3 с и плавно останавливается |
| Без двоения | Соседние кадры смешиваются **только в движении**. В покое прогресс доводится до ближайшего целого кадра — двойной экспозиции нет |
| Без мерцания | Холст не очищается при показе и скрытии адресной строки (`width/height` только при реальном изменении); холст непрозрачный; виден только после первого настоящего кадра. Постер — первый кадр фильма |
| Загрузка | Сначала грубый «скелет» кадров, затем остальные — начиная с места, где сейчас зритель; Save-Data — без скачивания фильма; страница грузится ~0,5 с |
| Текст | Начальные титры стоят, потом уходят вверх. Подсказка прокрутки исчезает сразу. Затемнение под текст ослабевает в середине пути, чтобы показать съёмку ярче. В конце — финальная фраза и кнопки, когда комната «встала». Затем пауза-плато, чтобы инерция не проскочила финал |
| Финал | Растворение съёмки в реальной фотографии. На компьютере холст во время растворения подстраивает кадрирование под фото, и два изображения совпадают |
| Ориентация | Набор кадров выбирается один раз. При смене портрет ↔ альбом страница один раз перезагружается |
| Уменьшение движения | Статичный первый экран |

## 2. Почему наш прототип выглядел плохо

| | Studio Chenille | Наш прототип |
|---|---|---|
| Исходник на телефоне | Своя вертикальная съёмка 900×1600, кадр **уменьшается** | Видео 834×1112 (3:4), на телефоне обрезано по бокам до ~512 px и **растянуто в 2,3 раза** |
| Размер холста | По реальному размеру | Ошибка: холст 754×348 растягивался в ~6 раз (исправлено в `cbb04a3`) |
| Движение камеры | Путь *внутрь* дома: фасад → дверь → холл → кухня, сильная глубина | Боковой проезд вдоль стены 4 с — «входа» нет |
| Длина | 7,4 с, 155 / 108 кадров на ~4 экрана прокрутки | 4 с, 97 кадров на 4,2 экрана: каждый кадр держался долго, видны ступеньки |
| Плавность | Тяжёлая камера + смешивание только в движении + остановка на чистом кадре | Прямая привязка; смешивание давало двоение, без него — рывки |
| Свет | Вечер, тёплый свет из окон, глубокий контраст | Ровный дневной свет, плоско |
| Финал | Растворение в реальной фотографии работы | Кончался ИИ-кухней с подписью «Иллюстрация» |

**Вывод.** Дело не в выборе «canvas или MP4», а в исходнике: нужна своя вертикальная съёмка в разрешении экрана и движение *внутрь* пространства. Поверх неё — режиссура: тяжёлая камера, чистый кадр в покое, финал на реальной работе.

## 3. Концепция для VERNISSAGE — «Войти в дом»

Дизайн `1a0637c` сохраняется полностью. Меняется **только первый экран**: вместо неподвижного фото — сцена-путь на ~4 экрана прокрутки.

После неё, как сейчас, наезжает заявление, затем комнаты, проект, «Для бизнеса», шаги, 3D-раздел, заявка и подвал. Ссылки в FORMIQ Configurator не меняются.

### Режиссёрский сценарий

Один непрерывный кадр 10 с, 24 к/с, без склеек и людей. Вечер в Астане.

| Время | Кадр | Камера |
|---|---|---|
| 0–2 с | Тихий холл квартиры. Впереди **арочный проём** — мотив v9 — с мягкой подсветкой; за ним тёплый свет комнат | Статика → начало медленного проезда вперёд на высоте глаз ~150 см |
| 2–5 с | Проходим арку. Справа — **скруглённый встроенный шкаф из ореха со светящимися полками** (как в реальной работе `res-niche`), слева — фасады без ручек со световой линией | Ровный проезд вперёд, лёгкий параллакс мимо скруглённого угла |
| 5–8 с | Открывается кухня-гостиная: остров из камня, высокие пеналы, световые линии, подвесной светильник, за окном вечерний город | Плавное торможение, лёгкий поворот на 5–8° к острову |
| 8–10 с | Камера встаёт в композицию, близкую к реальному фото `res-wide` (кухня-гостиная с обеденной зоной) | Почти остановка |

**Финал** — в коде, а не в генерации: съёмка растворяется в **реальной фотографии VERNISSAGE** с подстройкой кадрирования. Над ней фраза «Это реальная квартира в Астане. Мы сделали в ней всю мебель», кнопки «Рассчитать стоимость» и «Собрать в 3D». Пока на экране ИИ-съёмка, видна подпись «Иллюстрация — не работа VERNISSAGE». На реальной фотографии подпись исчезает.

### Текст (шрифты и тексты дизайна 1a0637c)

| Прогресс | Что на экране |
|---|---|
| 0–15 % | Заголовок «Мебель на заказ по вашим размерам», строка «Астана, с 2003 года» и подсказка «Листайте, чтобы войти» |
| 15–30 % | Заголовок поднимается и гаснет, затемнение ослабевает — съёмка в полную яркость |
| 45–60 % | У скруглённого шкафа одна строка: «Каждая деталь — по размерам вашего дома» |
| 75–90 % | Растворение в реальном фото, финальная фраза, кнопки, усиление виньетки |
| 90–100 % | Пауза-плато, затем наезжает заявление, как в 1a0637c |

### Технология (выбрана после изучения референса)

**Гибрид, как у Studio Chenille, с поправками.**

- **Телефон, портрет:**
  - **холст + WebP 1080×1920**, около 120 кадров, качество ≈ 85 (≈ 7–9 МБ);
  - загрузка «скелет → остальные от текущего места»;
  - плотность холста ≤ 2: на iPhone 1080 px уменьшаются до 786, и кадр предельно резкий;
  - в памяти ≈ 30 декодированных кадров.
- **Компьютер:**
  - WebP 1920×1080 (~150 кадров);
  - для экранов ≥ 1441 физ. px — MP4 1440p / 2160p с ключевым кадром через каждые 6 кадров, перемотка из памяти;
  - самопроверка скорости перемотки с переходом на кадры.
- **Общее:**
  - тяжёлая камера (`k = 1 − e^(−7·dt)`);
  - смешивание только в движении, в покое — чистый кадр;
  - без очистки холста при изменениях адресной строки;
  - постер — первый кадр;
  - sticky-закрепление, родная прокрутка;
  - «уменьшить движение» и Save-Data — постер и текст без фильма.

GSAP для этой сцены не нужен: своя короткая петля `requestAnimationFrame` надёжнее на iOS. Остальная страница остаётся на GSAP, как в 1a0637c.

## 4. Новая съёмка — Higgsfield

Без вашего разрешения ничего не генерирую. Баланс — **597,22 кредита**.

### Требования к исходнику

- Две отдельные генерации: **9:16 (1080×1920)** для телефона и **16:9 (1920×1080 или 4K)** для компьютера. Не обрезать одну из другой.
- 10 с, 24–30 к/с, **один непрерывный кадр**, постоянная медленная скорость, без склеек, людей, текста, логотипов и «морфинга» мебели.
- Последний кадр близок по композиции к реальному фото `res-wide` — чтобы растворение было бесшовным.
- Стартовый и финальный кадры — сначала неподвижные изображения (контроль композиции), затем image-to-video по ним.
