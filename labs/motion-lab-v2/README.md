# VERNISSAGE — Motion Lab V2

Интерактивный прототип: сборка интерьера, управляемая прокруткой страницы.
Три **демонстрационные** сцены — кухня (8 этапов), гостиная (7), ресторан (6).
Сцены не являются реальными проектами VERNISSAGE: планировка и размеры условные.

> Лаборатория — отдельный прототип и не является частью основного сайта VERNISSAGE 2.0.
> Все команды ниже выполняются из этой папки: `cd labs/motion-lab-v2`.

---

## 1. Самый быстрый просмотр — без установки

Откройте файл **`vernissage-motion-lab-v2.html`** двойным щелчком в Chrome, Safari, Edge или Firefox.
Это один файл со всем кодом внутри. Нужен интернет только для шрифтов (без него будет системный шрифт).

## 2. Готовая сборка через локальный сервер

Папка `site/` — собранная версия сайта. Из корня проекта:

```bash
python3 -m http.server 4173 --directory site --bind 127.0.0.1
```

Откройте http://127.0.0.1:4173/

Без Python подойдёт любой статический сервер, например: `npx serve site -l 4173`.

## 3. Разработка

Требуется **Node.js 20+** и **pnpm 10+** (`npm install -g pnpm`).

```bash
pnpm install          # восстановить зависимости (node_modules в архив не входят)
pnpm dev              # режим разработки с автообновлением: http://localhost:5173/
pnpm build:site       # собрать сайт в папку site/
pnpm preview          # раздать site/ на http://127.0.0.1:4173/
pnpm typecheck        # проверка типов TypeScript
pnpm bundle           # собрать автономный vernissage-motion-lab-v2.html
```

> `pnpm bundle` использует Parcel (как скрипт Web Artifacts Builder). В `package.json` уже включён
> параметр `"@parcel/resolver-default": { "packageExports": true }` — без него Parcel не собирает
> пакеты Radix UI.

## 4. Автоматические проверки (Playwright)

```bash
pnpm add -D playwright && npx playwright install chromium   # один раз
pnpm preview                                                # в отдельном терминале
node tests/qa.cjs            # 45 проверок на 1920×1080, 1440×900, 390×844, 375×812
node tests/geometry.cjs      # на каждом завершённом этапе все элементы в финальных координатах
node tests/performance.cjs   # интервалы кадров во время автовоспроизведения
```

Скриншоты сохраняются в `test-results/v2shots/`. Адрес можно передать вторым аргументом:
`node tests/qa.cjs test-results http://127.0.0.1:4173/`.

Результат последнего прогона (Chromium): 45 из 45 проверок пройдены, смещённых элементов — 0,
60 кадров/с без кадров дольше 33 мс. Safari, Firefox и реальные iPhone ещё не проверялись.

## 5. Как пользоваться прототипом

- **Прокрутка вниз** собирает интерьер, **вверх** — разбирает.
- **Ползунок** — любой момент сборки (мышь, палец, клавиатура).
- **Кнопки 1…N** над ползунком — перемотка к этапу.
- **▶** — автовоспроизведение; любое колесо, касание или клавиша его останавливает.
- **Кухня / Гостиная / Ресторан** — переключение объекта.
- **До / После** — перетаскиваемый разделитель и выбор любых двух этапов.
- **Настройки** (значок справа сверху): скорость сборки, плавность, пауза на этапе,
  длительность автовоспроизведения, уменьшение движения. Сохраняются в браузере.

## 6. Структура

```
src/
├─ engine/
│  ├─ progress.ts    # единое состояние прогресса: прокрутка → прогресс, сглаживание,
│  │                 # перемотка к этапу, автовоспроизведение. Без зависимостей.
│  └─ math.ts        # кривые cubic-bezier, разбиение прогресса на этапы
├─ scenes/
│  ├─ kit.tsx        # <A> — способ монтажа элемента: rise/drop/left/right/up/down/ltr/rtl/
│  │                 # draw/light/contact; размерные линии; перспективная камера
│  ├─ Defs.tsx       # общие материалы: шпон, камень, латунь, бетон, свет
│  ├─ Kitchen.tsx  Living.tsx  Restaurant.tsx   # сцены и тексты этапов
│  └─ index.tsx      # реестр сцен, кадрирование для смартфона, SceneView
├─ ui/controls.tsx   # ползунок с этапами, «До / После», настройки
├─ App.tsx           # страница: вступление, sticky-сцена, финал, панель настроек
└─ index.css         # дизайн-токены и стили (гибрид Cinematic Luxury B + Technical A)
tests/               # Playwright-проверки
site/                # готовая сборка для сервера
vernissage-motion-lab-v2.html   # автономная версия
```

**Главный принцип:** источник прогресса — только прокрутка. Ползунок, кнопки и
автовоспроизведение двигают прокрутку, поэтому способы управления не конфликтуют, а прокрутка
вверх всегда разбирает сцену. Каждый элемент нарисован в финальных координатах; этап только
определяет, когда и по какой оси он «устанавливается». Геометрия между этапами не меняется.

## 7. Перенос в Astro

Переносятся без изменений: `src/engine/progress.ts`, `src/engine/math.ts`, модель сцены
(этап, задержка, длительность, способ монтажа). React нужен только лаборатории.

## 8. Материалы для замены демонстрационных сцен

1. Финальный кадр каждого объекта со штатива (4K+, RAW/TIFF) и вертикальный кадр с той же точки.
2. Этапы на этом же кадре и в том же размере: реальные фото «до/в процессе» или AI-кадры,
   полученные **последовательным удалением** элементов из финального фото.
3. Чертежи с размерами (PDF/DWG) для этапа «Замеры».
4. Для Premium-версии: 3D-рендер анимации сборки с неподвижной камерой (25–30 к/с,
   2560×1440 и 1080×1920), по возможности маски объектов и отдельный проход теней.
5. Логотип в векторе.

# M3.1 — Interactive Kitchen Assembly

Отдельная страница лаборатории: **`m31.html`** (сцены V2 остаются в `index.html` без изменений).
Шесть состояний кухни — от пустого помещения до финала — управляются прокруткой страницы.

## Запуск

```bash
pnpm install
pnpm build:site && pnpm preview   # http://127.0.0.1:4173/m31.html
pnpm dev                          # http://localhost:5173/m31.html
pnpm bundle:m31                   # автономный файл vernissage-m31-kitchen.html
```

Без установки: откройте `vernissage-m31-kitchen.html`.

## Что умеет

- Прокрутка вниз собирает, вверх разбирает; состояние — функция единого прогресса 0…1.
- Ползунок прогресса, кнопки этапов 0–5, Play / Pause, Restart (без перезагрузки).
- Full Experience / Reduced Motion (по умолчанию — как в системе, выбор запоминается).
- Любое действие посетителя (колесо, касание, клавиши, полоса прокрутки) останавливает автопоказ.
- Раскладки: компьютер, планшет (портрет), смартфон (портрет), смартфон (горизонтально); safe-area iPhone.

## Архитектура (`src/m31/`)

| Файл | Ответственность |
|---|---|
| `data/stages.ts` | Названия и описания шести этапов, параметры движения |
| `data/kitchenModel.tsx` | Модель сцены: элементы в финальных координатах + этап и ось монтажа |
| `sceneDriver.ts` | `elementState()` (чистая функция) и `SceneDriver` — пишет в DOM только изменившиеся значения, без React |
| `controller.ts` | `AssemblyController`: прогресс прокрутки → драйвер; Play/Pause, Restart, переход к этапу |
| `KitchenStage.tsx` | Отрисовка демо-сцены (один раз) и фото-режима |
| `assetLoader.ts` | Загрузка фото-кадров этапов с приоритетом, таймаутом и откатом в демо-режим |
| `Controls.tsx` | Статус этапа, индикатор прогресса, кнопки управления |
| `KitchenAssembly.tsx` | Сборка модуля, раскладки, режим движения |

Общий движок `src/engine/progress.ts` (используется и V2): кэш размеров, `visualViewport`, поворот экрана,
`pageshow`, защита от гонки автопоказа и ручной прокрутки.

## Фото-режим и недостающие ассеты

Сейчас работает **демонстрационная** векторная сцена (не реальный проект VERNISSAGE).
Реальные кадры подключаются без пересборки: `m31.html?plates=/путь/stage-{n}.webp`, где `{n}` = 0…5.
Если хоть один кадр не загрузится, модуль показывает демо-режим с пояснением.

Требования к шести кадрам:

1. Один и тот же кадр камеры: штатив, тот же объектив и фокусное расстояние, та же точка съёмки.
2. Одинаковый размер в пикселях (рекомендуется 2560 × 1440; для смартфона — дополнительно 1080 × 1350 с той же точки).
3. Этапы: 0 — пустое помещение; 1 — корпуса; 2 — фасады и навесные модули; 3 — столешница, фартук;
   4 — техника, фурнитура, свет; 5 — финал.
4. Если кадры делаются через AI — последовательным **удалением** элементов из финального фото,
   без генерации каждого кадра заново (иначе меняются перспектива и пропорции).
5. Форматы: WebP или AVIF, до ~350 КБ на кадр 2560 px.
